# Repo import, AST storage, and browsing (incremental)

### Goals

- Fetch public repos, parse supported files to AST, store AST-only in MongoDB.
- Browse repos/files from DB; file view reuses AST/Quiz/Lesson UIs.
- Keep current app fully working during rollout; add new routes incrementally.

### Key decisions

- Public repos only (HTTPS). Shallow clone (`--depth 1`).
- Mongo stores AST-only. Local cloned files are used to serve code; user can delete them later from dashboard. If deleted, file view can fall back to GitHub raw content using stored commit SHA.
- Python via Tree-sitter first; add more languages later behind a config.

### AST shape to persist (must match UI)

```20:31:codegem/src/lib/treeSitter.ts
export type TreeSitterAstNode = {
  type: string
  named: boolean
  startPosition: Position
  endPosition: Position
  // Absolute character indices within the full source string
  startIndex: number
  endIndex: number
  text?: string
  children: TreeSitterAstNode[]
  namedChildren: TreeSitterAstNode[]
}
```

### Data model (MongoDB)

- repos: { _id, url, provider: 'github', owner, name, defaultBranch, commitSha, status: 'pending'|'parsing'|'ready'|'error', fileCount, parsedCount, createdAt, updatedAt, lastError? }
- repo_files: { _id, repoId, path, size, language: 'python', parser: 'tree-sitter', ast: TreeSitterAstNode, createdAt }
- quizzes: { _id, kind: 'custom', repoId, filePath, root, totalCards, cards[], createdAt }

Indexes: repos.url unique; repo_files (repoId, path) unique; quizzes (repoId, filePath) optional.

### API surface (server)

- POST /api/repos { repoUrl, branch? } → 202 { repoId } (triggers fetch+parse)
- GET /api/repos → list repos (status, counts)
- GET /api/repos/:id → repo details
- POST /api/repos/:id/refresh → re-fetch & re-parse
- GET /api/repos/:id/tree?path=… → directory listing (folders/files) derived from repo_files paths
- GET /api/repos/:id/files/ast?path=… → AST JSON
- GET /api/repos/:id/files/code?path=… → file text from local clone; fallback to GitHub raw with stored commitSha if clone missing
- DELETE /api/repos/:id/clone → delete local cloned files only (AST remains)
- POST /api/quizzes { payload } → save custom quiz to Mongo
- GET /api/quizzes?repoId=…&path=… → list (optional)

### Backend internals

- Service: Node (Fastify/Express). Env: MONGO_URL, DATA_DIR, GITHUB_TOKENS? (unused now).
- Clone: simple-git or `git` CLI to DATA_DIR/<repoId>. Validate input to prevent path traversal; only github.com HTTPS allowed.
- Parse: walk repo, filter extensions; node-tree-sitter python grammar; serialize to `TreeSitterAstNode` shape (namedChildren only; leaf text only).
- Progress: count target files upfront, update repos.parsedCount as each file saved. Store status transitions.
- Code serving: read from DATA_DIR/<repoId>/<path>; if missing, GET raw GitHub by owner/name@commitSha.

### Incremental rollout plan (safe, shippable slices)

1) Server scaffold + Mongo connection

- Create /server (TypeScript) with Fastify/Express, health check.
- Dockerfile for server; add to docker-compose with Mongo (with volume).

2) Repo model + create/list endpoints

- Collections and indexes; POST /api/repos inserts repo row (pending).
- GET /api/repos lists minimal metadata.

3) Fetch + parse (Python) pipeline

- On POST, in-process job: clone, enumerate .py files, parse to AST, insert repo_files, update counts/status.
- Expose GET /api/repos/:id for status/progress.

4) Tree and file endpoints

- GET /api/repos/:id/tree and /files/ast, /files/code with GitHub raw fallback.

5) Frontend: repos list + create page

- Add /repos and /repos/new; keep current homepage unchanged.

6) Frontend: repo tree + file view

- Add /repos/:repoId/tree and blob pages; implement DbFileViewer that feeds code+AST into current `SandboxViewer`-like layout (or share subcomponents).

7) Custom quiz backend

- POST /api/quizzes; update `LessonViewer` and `QuizViewer` to call server (fallback to localStorage if 4xx/5xx/offline).

8) Dashboard controls

- Repo detail page shows progress; add "Delete local clone" button (DELETE /clone).

9) Background-ready refactor (optional next)

- Abstract parsing into a job runner; add in-memory queue now. Later swap to BullMQ/Redis without changing API.

10) Deployment

- Compose file for server+mongo; volumes: `mongo_data` (required), `data_dir` (recommended) to persist clones between restarts.
- Works on localhost and Coolify.

### Persistence & volumes

- Mongo: persistent volume required.
- Cloned repos: optional persistent volume (recommended). Users can delete via dashboard to save space.

### Security & limits

- Accept only github.com HTTPS URLs; shallow clone; sanitize paths; size/timeout caps; limit concurrent jobs.

### Future: Projects

- Mirror repos schema with `projects` and `project_files`; UI lists both on /repos (renamed to /library).
- Allow manual file add or web clipper ingestion to projects.
