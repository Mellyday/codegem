1. Introduction & Vision
1.1. The Problem
Code is written as flat text, but its true structure is a deeply nested hierarchy. For developers learning a new language, students trying to grasp programming concepts, or engineers analyzing complex, unfamiliar code, it is difficult to "see" this underlying structure. Understanding questions like "What is the exact condition for this if statement?" or "What are all the parts of this class definition?" requires careful mental parsing that is slow and error-prone.
1.2. The Vision
AST Navigator is an interactive educational tool that transforms static source code into a dynamic, explorable map. It presents the code's Abstract Syntax Tree (AST) in a user-friendly, navigable sidebar that is perfectly synchronized with the code editor.
Our vision is to create a "Google Maps for code," allowing users to fluidly zoom in and out of logical blocks, from an entire file down to a single expression. By making the code's grammatical structure tangible and interactive, we will dramatically lower the barrier to understanding, debugging, and learning programming languages.
2. Target Audience
Primary: Programming Students & Educators: Students can visually deconstruct code examples to understand concepts like function arguments, loop components, and class structure. Educators can use the tool for live demonstrations.
Secondary: Software Developers: Engineers can use the tool during code reviews or when debugging to quickly understand the structure of unfamiliar functions or complex nested logic.
Tertiary: Tool-smiths & Language Designers: Anyone building linters, compilers, or other code-analysis tools can use it to inspect the AST of sample code.
3. Core Features & Requirements
3.1. Two-Pane Interface
The application will feature a classic two-pane layout:
Code Editor Pane (Left): A read-only view displaying the source code with syntax highlighting.
AST Tree Pane (Right): An interactive, collapsible tree view representing the code's AST.
3.2. Synchronized Highlighting (Two-Way Binding)
The core of the user experience is the seamless link between the code and its structure.
Tree-to-Code: When a user clicks on a node in the AST Tree (e.g., FunctionDef), the corresponding block of code in the editor pane will be highlighted.
Code-to-Tree: When a user places their cursor within a block of code, the corresponding node in the AST Tree will be highlighted and expanded.
3.3. User-Centric AST Navigation: The "Navigable Children" Model
This is the key design principle. Instead of showing a raw, overly technical AST, we present a curated, user-centric view.
Definition: A "child" of a node is a semantically distinct, navigable component of that node. These children correspond to the fields in a language's formal AST that contain other nodes or lists of nodes.
Exclusion: Simple attributes (like a function's name as a string or an operator symbol) are treated as properties of the parent node and displayed in its label, not as separate children to be navigated.
Consistency: Every node of the same type will always show the same set of potential children (e.g., a ClassDef always shows bases, body, etc.), even if a child is empty for a given piece of code. This provides a consistent mental model for the user.
4. Detailed Examples & User Flow
Example 1: Deconstructing a Simple if/else Statement
A user inputs the following Python code:
code
Python
if user_level > 5:
    unlock_achievement("Admin")
else:
    grant_basic_access()
User Flow:
The AST Tree shows a top-level If node.
The user clicks on the If node.
Code Pane: The entire if/else block is highlighted.
AST Tree: The If node expands to show its three navigable children: test, body, and orelse.
The user clicks on the test child.
Code Pane: Only the condition user_level > 5 is highlighted.
AST Tree: The test node (a Compare node) could be further expanded to show its children: left, ops, and comparators.
The user clicks on the body child.
Code Pane: The line unlock_achievement("Admin") is highlighted.
The user clicks on the orelse child.
Code Pane: The line grant_basic_access() is highlighted.

A user inputs the searchMatrix code from our initial discussion.
code

The AST Tree shows a top-level ClassDef: Solution node.
The user clicks on ClassDef: Solution.
Code Pane: The entire class Solution: ... block is highlighted.
AST Tree: The node expands to show its four navigable children:

The user clicks on bases.

5. Out of Scope for Version 1.0
Code Editing: The tool will be a viewer, not an editor. The code pane will be read-only to simplify the initial implementation.
Support for Multiple Languages: The initial version will focus exclusively on Python 3.
Semantic Analysis: The tool will only parse syntax. It will not perform type checking, "go to definition," or other IDE-level semantic analysis.
Saving/Loading Files: Users will interact with the tool by pasting code directly into the interface.
6. Success Metrics
User Engagement: Average session duration. We want to see users spending time exploring code, not just glancing and leaving.
Educational Adoption: Positive feedback and adoption by instructors or students in programming courses.
Clarity Score (via User Surveys): Ask users: "On a scale of 1-5, how much did this tool improve your understanding of the code's structure?" a score of 4.0 or higher would be considered a success.

Excellent. Let's generalize this design philosophy for a Python AST explorer. Your goal is to create a user-centric, navigable tree where "children" are the logical, distinct components of a syntax node.
This model maps beautifully to the structure of Python's official ast module. The "children" you're looking for are typically the fields of an AST node that contain other nodes or lists of nodes. Simple values like strings or numbers are attributes of the parent node, not children to navigate into.
Here is a general breakdown of how this would look for common Python statements and expressions.
General Principles
Parent Node: Represents the entire construct (e.g., the FunctionDef node is the whole def statement).
Node Label: The label in your sidebar should include the type and key info (e.g., ClassDef: Solution, FunctionDef: searchMatrix, BinOp: +).
Children: The semantically distinct parts you can "zoom into."
Empty Children: An empty list (like bases for a class with no parents) is still a valid child. Clicking it should simply show nothing. This maintains structural consistency.
Common Python AST Nodes and Their Navigable Children
1. Containers
Module (The entire file)
Code: The whole script.
Child:
body: A list of all top-level statements (imports, functions, classes).
FunctionDef (Function Definition)
Code: def my_func(a, b=10) -> int:
Navigable Children:
args: The arguments list. Clicking it highlights (a, b=10).
body: The block of code inside the function.
decorator_list: The list of decorators (e.g., highlights @my_decorator).
returns: The return type annotation. Clicking it highlights -> int.
ClassDef (Class Definition)
Code: @dataclass class MyClass(Base): pass
Navigable Children:
bases: The list of parent classes. Highlights (Base).
body: The block of code inside the class (methods, attributes). Highlights pass.
decorator_list: The list of decorators. Highlights @dataclass.
keywords: (Rare) Keyword arguments in the class definition.
2. Control Flow
If (If Statement)
Code: if x > 0: print("Positive") else: print("Not")
Navigable Children:
test: The condition being checked. Highlights x > 0.
body: The block of code to execute if the test is true. Highlights print("Positive").
orelse: The else or elif block. Highlights print("Not"). (Note: an elif is just another If node nested inside the orelse field).
For (For Loop)
Code: for i in range(10): print(i)
Navigable Children:
target: The loop variable. Highlights i.
iter: The iterable being looped over. Highlights range(10).
body: The block of code inside the loop.
orelse: The optional else block that runs when the loop finishes without a break.
While (While Loop)
Code: while x < 10: x += 1
Navigable Children:
test: The condition being checked. Highlights x < 10.
body: The block of code inside the loop.
orelse: The optional else block.
Try (Try/Except/Finally Block)
Code: try: ... except ValueError: ... finally: ...
Navigable Children:
body: The main try block.
handlers: A list of the except blocks. Each one is an ExceptHandler node.
orelse: The optional else block that runs if no exception occurred.
finalbody: The finally block.
3. Statements
Assign (Assignment)
Code: x = y + 1
Navigable Children:
targets: A list of what's being assigned to. Highlights x. (For a, b = c, it would highlight a, b).
value: The expression on the right-hand side. Highlights y + 1.
Return
Code: return True
Navigable Children:
value: The expression being returned. Highlights True.
With (With Statement)
Code: with open("f.txt") as f: ...
Navigable Children:
items: A list of the context managers. Each is a withitem node that has a context_expr (open(...)) and an optional_vars (f).
body: The block of code inside the with statement.
4. Expressions (these form the nested trees inside statements)
BinOp (Binary Operation)
Code: a + b
Sidebar Label: BinOp: +
Navigable Children:
left: The left-hand operand. Highlights a.
right: The right-hand operand. Highlights b.
The operator (+) is an attribute of the BinOp node itself, not a child.
Compare (Comparison)
Code: 0 < x <= 10
Sidebar Label: Compare: <, <=
Navigable Children:
left: The initial value. Highlights 0.
comparators: A list of the other values being compared against. Highlights x and 10.
The operators (<, <=) are attributes of the node.
Call (Function Call)
Code: print("Hello", end="!")
Navigable Children:
func: The object being called. Highlights print.
args: A list of positional arguments. Highlights "Hello".
keywords: A list of keyword arguments. Highlights end="!".
Attribute (Attribute Access)
Code: matrix.shape
Sidebar Label: Attribute: shape
Navigable Children:
value: The object whose attribute is being accessed. Highlights matrix.
The attribute name (shape) is a string attribute of the node itself.
Subscript (Indexing)
Code: matrix[mid // n]
Navigable Children:
value: The object being indexed. Highlights matrix.
slice: The index or slice itself. Highlights mid // n.
This model provides a consistent and powerful way for a user to deconstruct and understand any piece of Python code by navigating its logical components. Your intuition about the ClassDef was the perfect starting point for this robust design.
